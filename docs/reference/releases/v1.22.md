# v1.22

!!! warning "Breaking changes"
    This release contains breaking changes. Review the Breaking changes section below before upgrading. For clusters, follow the [upgrade guide](../../how_to/upgrade.md).

- **Release date**: November 11, 2026
- **GitHub release**: [v1.22.0](https://github.com/ellanetworks/core/releases/tag/v1.22.0)

## New features

- **Roaming (local breakout)**: Ella Core acts as a visited network for roaming partners over 4G and 5G. The subscriber's home network authenticates them and holds their subscription, and Ella Core carries their traffic to its local data networks. Configure roaming partners from the Integrations page and view roamers from the Subscribers page. See the [roaming guide](../../how_to/configure_roaming.md).
- **Integrations page**: A new page, to configure IMS, SMS and Roaming.
- **Multiple network instances**: Each data network can leave the user plane on its own interface, VLAN or VRF. Declare network instances in the config file and pick one per slice and data network. For example, when co-hosting Ella Core with [Ella IMS](https://github.com/ellanetworks/ims) and [Ella SMSC](https://github.com/ellanetworks/smsc), the `ims` data network leaves through a veth into the IMS namespace while `internet` leaves through N6. See the [co-hosting guide](../../how_to/co_host_with_ims_and_smsc.md).
- **RAN trace correlation**: Ella Core sends each UE's 3GPP trace ID to the radio and uses it as the OpenTelemetry trace ID, allowing distributed tracing through the RAN and the core.
- **DSCP marking**: Downlink GTP-U packets on N3/S1-U are marked with a DSCP value derived from the QoS flow's 5QI and ARP (ex. EF for voice).
- **Kubernetes hardening**: New `/api/v1/livez` and `/api/v1/readyz` health endpoints. The Kubernetes manifests no longer run Ella Core as a privileged container, and add explicit capabilities, resource limits and startup, readiness and liveness probes, in line with CNTi best practices.

## Maintenance

- Performance improvements for large deployments.
- Fixed migrating a standalone deployment to a cluster.
- Raft metrics are exported to Prometheus.
- Bug fixes
- Dependency updates

## Breaking changes

- SMS, IMS and Diameter endpoints moved under `/api/v1/integrations`: `/api/v1/operator/sms` -> `/api/v1/integrations/sms`, `/api/v1/operator/ims/*` -> `/api/v1/integrations/ims/*`, and `/api/v1/networking/diameter` -> `/api/v1/integrations/diameter`. SMSC peers (`/api/v1/operator/sms/smsc-peers/{id}`) are replaced by SMSCs (`/api/v1/integrations/sms/smscs/{name}`), each with one or more Diameter nodes.
- NAT and local switch are now set per slice and data network: `/api/v1/networking/nat` and `/api/v1/networking/local-switch` are removed. Use `/api/v1/slices/{name}/data-networks/{data_network}` instead.
- `GET /api/v1/operator` no longer returns `ims` and `sms`. Use `GET /api/v1/integrations/ims` and `GET /api/v1/integrations/sms` instead.
- SMS settings: `smsNumber` -> `servingNodeNumber`. SMSC fields: `diameterIdentity`, `address` and `port` -> `nodes[].originHost`, `nodes[].address` and `nodes[].port`.
- IMS application server and service profile fields are now camelCase (ex. `server_name` -> `serverName`, `public_service_identities` -> `publicServiceIdentities`, `initial_filter_criteria` -> `initialFilterCriteria`, `application_server_name` -> `applicationServerName`, `request_uri` -> `requestURI`).
- Diameter status: `host` -> `originHost`.

If you depend directly on the API, you may need to adapt your integration.
